# alert-demo

A demo workload for the hk demo page's **On its own** tab (`base-apps/hk-demo/`). The tab shows
an alert the platform handles by itself: Grafana fires, the dispatcher hands the alert to the
implementer, the implementer opens a pull request, Slack gets the finding, and a person decides.
This app exists so that journey can be made to happen before a meeting instead of waited for.

## What it does

It is idle until the hk demo app asks it to fill (`POST /fill`, from the page's Start button).
While a demo run is on, it holds `FILL_MIB` (236Mi) of memory for `HOLD_SECONDS` (30 minutes) and
then lets it go. Its memory limit is 256Mi, so during a run the container sits near its limit, and
Grafana's **Container near memory limit** rule (over 90% for 15 minutes) fires. From there it is
an ordinary alert: the dispatcher's existing `container-near-memory-limit` row sends it to the
implementer, which investigates the pod, its logs and this manifest like any app's.

The amount it holds is fixed, not a share of the limit.

The service (`scripts/alert_demo.py`, standard library, run from a ConfigMap):

| Request | What it does |
|---|---|
| `GET /status` | the state (`idle` or `holding`), start and release times, held, target, limit and usage bytes |
| `POST /fill` | starts a run (202); 409 when one is on, or when the fill would reach the limit |
| `POST /stop` | ends a run early |

It logs one JSON line per state change and nothing per request.

## Who can reach it

Only the hk demo app's pod (`network-policy.yaml`), and only as the hk demo's own mesh principal,
`cluster.local/ns/hk-demo/sa/hk-demo` (`authorization-policy.yaml`). It never calls anything
itself and holds no credentials.

## Side effects of a run

Each run is real:
- a Grafana alert in `#oncall-alerts`;
- an implementer session, charged to the implementer group's daily budget through the model gateway;
- usually a pull request on this repo by `arigsela-implementer`, plus the finding in Slack.

Close the demo pull request after the meeting (runbook).

## Where config lives

| What | Where |
|---|---|
| Code | `scripts/alert_demo.py` → `code-configmap.yaml` (generated by `scripts/gen-alert-demo-configmap.py`, which also writes `checksum/code`) |
| Fill size, hold time | `deployment.yaml` env `FILL_MIB`, `HOLD_SECONDS` |
| Limit | `deployment.yaml` resources |
| Alert rule | `base-apps/logging/grafana-alerting.yaml` (`container-near-memory-limit`) |
| Dispatch row | `base-apps/dispatcher/dispatch-table.yaml` (`container-near-memory-limit`) |
