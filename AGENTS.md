# Repository Guidelines

Build, test, and contribution rules for this GitOps repo. For what runs where,
read [`index.md`](index.md) (the bundle root and navigation front door).

## Project layout

- `base-apps/` — Argo CD. `master-app.yaml` (the root app-of-apps) creates an
  Application for every top-level `base-apps/<app>.yaml`; that app's resources
  live in `base-apps/<app>/`. In-scope apps also carry `docs.md`, `runbook.md`
  and `catalog-info.yaml` (the agent-docs contract, `templates/agent-docs/`).
- `appsets/managed-apps/` — one config per app generated by the `managed-apps`
  ApplicationSet (`base-apps/managed-apps.yaml`) instead of a hand-written
  Application. See `docs/managed-apps-appset.md`.
- `terraform/roots/asela-cluster/` — the only active Terraform root (applied by
  Atlantis with OpenTofu). Reusable code in `terraform/modules/`.
- `ansible/` — host layer: the hypervisor and the three k3s VMs.
- `templates/` — agent-docs and agent-identity contracts, and the Backstage New
  App scaffolder template (`templates/new-app/`).
- `scripts/` — generators (`gen-*.py`), validators (`validate-*.py`), backup and
  restore scripts, and one-off Vault provisioning scripts.
- `tests/<suite>/` — pytest suites, one directory per concern.
- `docs/` — cross-cutting guides, troubleshooting notes, specs and plans
  (`docs/index.md`). `SPEC.md` is the current task and invariant ledger.

## Build, test, and validation commands

CI (`.github/workflows/validate.yaml`) runs everything below with Python 3.12.
Base deps: `pip install pyyaml==6.0.2 pytest==8.3.3`.

**Run pytest one suite at a time**, as CI does (`python -m pytest tests/<suite>/ -q`).
Each suite has its own conftest; `pytest tests/` as a whole is not what CI runs.

| Suite | Extra needs |
|---|---|
| `agent-docs`, `catalog-refs`, `waf`, `techdocs`, `dashboards`, `resize`, `models`, `wan_ip`, `istio_logging`, `cve_report`, `okf`, `agent-identity`, `agent-capability`, `agent-audit`, `eval-corpus`, `appset` | none |
| `new-app-template` | `jinja2==3.1.4`, `yamllint==1.35.1`, kubeconform v0.6.7 |
| `admission-policies` | Docker (boots a real k3s and server-side dry-runs the fixtures) |
| `ansible` | Docker; `ansible-core==2.21.4 ansible-lint==26.9.0 kubernetes==36.0.3`, then `ansible-galaxy collection install -r ansible/requirements.yml` |
| `k3s-upgrade` | Docker and `sqlite3` (backup and restore drills against a real k3s) |
| `composition` | Not in CI. `tests/composition/render.sh xr-minimal` (also `xr-with-db`, `xr-with-s3`); needs the crossplane CLI, Docker and `yq` v4 |

**Validators** (all take `--repo-root .`):
`scripts/validate-agent-docs.py`, `validate-catalog-refs.py`, `validate-waf-scope.py`,
`validate-agent-identity.py`, `validate-agent-capability.py`, `validate-eval-corpus.py`.

**Generated files.** Never hand-edit these; change the source and re-run the
generator. CI runs each with `--check` and fails on drift.

| Generator | Writes | Source |
|---|---|---|
| `scripts/gen-okf.py --repo-root .` | `base-apps/index.md` | `docs.md` frontmatter, `scripts/okf-stubs.yaml` |
| `scripts/gen-techdocs.py --repo-root .` | `base-apps/<app>/mkdocs.yml`, `docs/index.md`, `docs/runbook.md` | each app's `docs.md` and `runbook.md` |
| `scripts/gen-cluster-overview-dashboard.py --repo-root .` | `base-apps/logging/grafana-dashboard-cluster-overview.yaml` | panel definitions in the script |
| `scripts/gen-agent-capability-policy.py --repo-root .` | `base-apps/admission-policies/agent-capability.yaml` | `agent-capability-taxonomy.yaml` |
| `scripts/gen-agent-audit-cronjob.py --repo-root .` | `base-apps/postgresql/agent-audit-cronjob.yaml` | `scripts/agent-audit.py` |

The `okf-autosync` workflow pushes a bot commit to any PR touching `base-apps/**`
if `base-apps/index.md` or `scripts/agent-docs-scope.txt` is out of date. Pull
before pushing again.

**Manifests:** `yamllint -c .yamllint.yaml <files>`, then kubeconform:

```bash
kubeconform -summary -strict -ignore-missing-schemas \
  -schema-location default \
  -schema-location 'https://raw.githubusercontent.com/datreeio/CRDs-catalog/main/{{.Group}}/{{.ResourceKind}}_{{.ResourceAPIVersion}}.json' \
  -kubernetes-version 1.33.0 <files>
```

Skip `base-apps/*/mkdocs.yml` and `appsets/**` for kubeconform (not Kubernetes
manifests); yamllint still covers them.

**Terraform:** `terraform fmt -check -recursive terraform/`, then in
`terraform/roots/asela-cluster`: `terraform init -backend=false && terraform validate`
and `tflint --format compact`. tfsec (soft-fail) and Infracost also run on PRs
touching `terraform/**`.

## Changing things

- **Everything goes through Git.** Argo CD auto-syncs `main` with `prune: true`
  and `selfHeal: true`. Don't `kubectl apply/edit/patch`; the change is reverted
  or pruned.
- **Terraform applies before merge.** Open the PR, wait for
  `atlantis/plan: asela-cluster`, then comment `atlantis apply` (or run the
  "Terraform Apply (gated)" Action with the PR number). Merge only after
  `atlantis/apply` is green. Merging first strands the change silently. See the
  header of `terraform/roots/asela-cluster/argocd.tf`.
- **New app:** `base-apps/<app>.yaml` + `base-apps/<app>/`, or a config in
  `appsets/managed-apps/`. To onboard it to the agent-docs contract, follow
  `templates/agent-docs/README.md` (including `directory.exclude` on the
  Application).
- **Secrets:** a per-namespace `SecretStore` plus `ExternalSecret`s resolving from
  Vault (`k8s-secrets`, KV v2, Kubernetes auth). Agent credentials are scoped per
  consumer (`templates/agent-identity/README.md`). Never commit secret values,
  kubeconfigs, Vault tokens, AWS keys or Terraform state.

## Style

- YAML: 2-space indent, lines under 200 characters where practical.
- Descriptive manifest filenames: `deployments.yaml`, `services.yaml`,
  `httproute.yaml`, `certificate.yaml`, `secret-store.yaml`, `external-secret*.yaml`.
- Explain non-obvious settings in a comment next to them. This repo keeps its
  rationale in the manifests.
- Commits use Conventional Commits with a scope, e.g. `fix(n8n): …`.
- PR titles and bodies must describe the change accurately. The PR triage
  workflow classifies them (see `CLAUDE.md`). List the local validation you ran,
  and call out deployment, DNS, IAM or secret impact.
