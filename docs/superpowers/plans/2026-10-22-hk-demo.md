# hk demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A page at `hk-demo.arigsela.com`, behind Dex login and the IP allow-list. It asks
`kagent/homelab-knowledge` one question and shows each platform piece's part in it: what it checked,
what it cost, and its logs and trace spans.

**Architecture:**
- **App:** a FastAPI app in a new private repo `arigsela/hk-demo`, run in namespace `hk-demo`.
  - An oauth2-proxy sidecar is its only way in.
  - It calls kagent in-cluster over A2A v1 with its own projected service-account token, streaming
    the run.
  - It then finds the run's trace in Tempo and its logs in Loki, reads totals from Prometheus, and
    turns them into eight "boxes". It streams those to the browser over server-sent events.
- **GitOps:** two PRs in `arigsela/kubernetes`. PR-A adds the image registry and push role. PR-B
  adds the app, Dex client, Gateway host, docs and SPEC rows.

**Tech Stack:** Python 3.12, FastAPI, Jinja2, httpx, uvicorn, uv 0.12.19, plain JavaScript
(EventSource, `textContent` only), Argo CD, Istio ambient, oauth2-proxy v7.15.5, External Secrets +
Vault, Crossplane (IAM), Terraform via Atlantis (ECR).

**Spec:** `docs/superpowers/specs/2026-10-22-hk-demo-design.md` (in `arigsela/kubernetes`), with
the mockup `docs/superpowers/specs/2026-10-22-hk-demo-mockup.html`. Read both before starting.

## Global Constraints

- **Names:**
  - repo `arigsela/hk-demo`; Python package `hk_demo`
  - namespace, ServiceAccount, Dex client and ECR repository: all `hk-demo`
  - host `hk-demo.arigsela.com`
  - Vault key `k8s-secrets/hk-demo`
  - Dex's copy of the secret: `k8s-secrets/dex` property `hk-demo-client-secret`
- **Agent endpoint:** `kagent/homelab-knowledge` at
  `http://kagent-controller.kagent.svc.cluster.local:8083/agents/kagent/homelab-knowledge`. The
  token is read from `/var/run/kagent/token` on every send (audience `kagent`, 3600 s).
- **Data stores:**
  - Loki `http://loki.logging.svc.cluster.local:3100`
  - Tempo `http://tempo.tracing.svc.cluster.local:3200`
  - Prometheus `http://prometheus.logging.svc.cluster.local:9090`
  - Grafana links go to `https://grafana.arigsela.com` (Prometheus datasource uid
    `PBFA97CFB590B2093`).
- **Binding:** the app binds `127.0.0.1:8000` and uvicorn runs with `--no-access-log`. The Service
  exposes only port 4180 (oauth2-proxy).
- **Python:** 3.12. No numpy, pandas or other AVX2-only wheels (the nodes are Xeon E5-2670).
- **Browser safety:**
  - CSP `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`,
    plus `Cache-Control: no-store`, `Referrer-Policy: no-referrer`,
    `X-Content-Type-Options: nosniff` on every response.
  - No CDN, no inline script or style.
  - The browser inserts all text with `textContent`, never `innerHTML`.
- **Never on screen:**
  - emails: rendered as `a•••@gmail.com` (first character, `•••`, the domain)
  - client IPs: masked to `/24` (`76.97.4.0/24`)
  - tool responses
  - `Authorization` headers, cookies and tokens, which also never appear in logs
- **Check marks:** ✓ ("observed") only from this request's own spans, log lines or metric samples.
  Everything else is ⚙ ("configured").
- **Loki:** every query puts the `|=` substring checks before any `|~` regex. Windows are bounded to
  the run: start −1 min to end +2 min (or now). Trace ids are left-padded to 32 hex (`zfill(32)`)
  before going to Loki or Prometheus.
- **Tempo:** a live search covers the last 1 h; a replay covers the run window. Poll the trace every
  3 s for at most 120 s.
- **Concurrency:** one run in flight at a time (409 otherwise).
- **Image:** `852893458518.dkr.ecr.us-east-2.amazonaws.com/hk-demo:<tag>@<digest>` with IMMUTABLE
  tags. The Deployment pins `tag@digest`.
- **Owner-only steps** (the plan stops and asks):
  - commenting `atlantis apply`
  - running the Vault script
  - creating the Route 53 A record
  - merging PRs

## Review Focus

1. **The trace never appears** (Tempo slow, or the trace was sampled out). After 120 s, the
   boxes that need it say "trace not found after 2 min" and link to Grafana. They don't spin
   forever. Test: Task 6 `test_trace_missing_after_cap`.
2. **The agent stream drops mid-run.** Once the ids are known, the app falls back to polling
   `GetTask` every 3 s within a 900 s budget, and the answer still arrives. Test: Task 3
   `test_stream_drop_falls_back_to_get_task`.
3. **Loki has no lines yet for a fresh run.** The logs panel says "logs not in yet" and is retried
   once at +10 s. It never shows an empty list as if it were final. Test: Task 6
   `test_logs_retried_once`.
4. **A second Send while a run is in flight** (a double click). The app returns 409, the first run
   keeps streaming, and the page shows "a question is already running". Test: Task 6
   `test_second_ask_conflicts`.
5. **No `X-Forwarded-Email`** (the sidecar is bypassed or misconfigured). The app returns 401 and
   never makes an anonymous run when `REQUIRE_EMAIL=true`. Test: Task 6
   `test_ask_without_email_rejected`.

      the MCP adapter lines found by trace id.

      `window_total('agent_cost_estimate_usd_total', '', '24h')`, the formula from
      `scripts/gen-agent-dashboards.py:86-111`, copied as a string template.

    - `eval_last(agent: str) -> dict | None`: the last `<EVAL> | agent="<agent>"` line in 30 d.
    - `waypoint_principal(start: datetime, end: datetime) -> str | None`: the `source_principal` of

      over the run window, or `None` when there's no sample.
    - `app_runs(days: int = 7) -> list[dict]`: the parsed JSON of the lines from
      `{namespace="hk-demo", container="app"} |= "hk-demo-run" | json`. Task 6 merges each run's
      start and end lines into a `RunRecord` (defined in Task 5).

### Task 6: Runs, routes and the server-sent-events feed

**Files:**

- Modify: `src/hk_demo/app.py` (wire in the routes and deps)

**Interfaces:**
- Consumes: `AgentClient` (Task 3), `Observability` (Task 4), `build_boxes`, `box_to_json`,
  `RunRecord` (Task 5).
- Produces:
  - `ServerEvent(type: Literal["ids","progress","answer","boxes","error","done"], data: dict)`.
  - `RunManager(agent, obs, settings, *, clock, sleep, log=print)`:
    - `start(question: str, email: str, request_id: str | None, client_ip: str | None) -> RunRecord`.
      Raises `Busy` while a run is in flight. Logs a JSON line
      `{"event":"hk-demo-run","phase":"start", **record}`, with the question passed through
      `mask_text`.
    - `async events(run_id: str) -> AsyncIterator[ServerEvent]`: live runs replay their buffered
      events, then follow. Unknown ids → `replay(run_id)`.
    - `async replay(run_id: str) -> AsyncIterator[ServerEvent]`: the record comes from
      `obs.app_runs()`, the answer from `agent.get_answer(task_id)`. It then emits `progress` built
      from the trace's model and tool spans, then `boxes`.
  - Pipeline per live run:
    1. Stream the agent events (`ids`, `progress`, `answer`).
    2. Log `{"event":"hk-demo-run","phase":"end", …}`.
    3. Poll `find_trace_id` (fall back to `trace_id_for_context`) every 3 s until 120 s.
    4. Fetch the trace, the run logs, the Gateway and waypoint lines by `request_id`, the adapter
       lines by trace id, and the totals.
    5. Emit `boxes` after each fetch that changes something; retry the logs once at +10 s if
       they're empty; then emit `done`.
  - Routes:
    - `GET /`: the page (Task 7).
    - `POST /api/ask`, JSON `{"question": str}` (1–2000 characters), returns `202 {"run_id": ...}`.
      Email comes from `X-Forwarded-Email`, or `settings.dev_email` when
      `require_email=false`. Request id from `x-request-id`; client IP from the first
      `X-Forwarded-For` hop.
    - `GET /api/runs`: `[{"run_id","started","question","state"}]`, newest first, at most 20, for
      the last 7 d.
    - `GET /api/runs/{run_id}/events`: `text/event-stream`, one `event: <type>` and `data: <json>`
      per `ServerEvent`.
