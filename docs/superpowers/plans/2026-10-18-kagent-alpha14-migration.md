# kagent 1.0.0-alpha11 → 1.0.0-alpha14 Migration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Executed 2026-10-19 — PRs #869, #870, #872, #873 merged, clean-DB cutover done, 9 Agents Ready on alpha14 — see SPEC T126–T128. Task 10's order changed in execution (merge before recreating the databases; the runbook's *Bump kagent and Substrate* has the order that worked).
**Owner:** Ari Sela
**Goal:** Move the cluster's kagent from 1.0.0-alpha11 to 1.0.0-alpha14 without losing the three stdio MCP servers, with the two-login Postgres model upstream now requires, and with every chart value moved to the new `config` schema.

**Architecture:** Three PRs in order. PR 1 replaces the kmcp `MCPServer` CRs with plain Deployments that reproduce exactly what kmcp rendered (an agentgateway adapter wrapping the stdio server), on the alpha11 chart, with no outage. PR 2 adds the `kagent_readwrite` role and login to `kagent_v1` and the two connection-string Secrets, also on alpha11 (the old Secret keeps working). PR 3 is the bump itself: both charts, the rewritten values, the Harness image, the CRD fixture, docs and SPEC, merged after the databases are archived and recreated empty (every alpha bump is a clean-database migration, `base-apps/kagent/runbook.md` "Bump kagent and Substrate").

**Tech Stack:** Argo CD (app-of-apps, ServerSideApply), Helm OCI charts `kagent`/`kagent-crds` 1.0.0-alpha14, agentgateway 0.9.0, PostgreSQL 18 (pgvector), External Secrets Operator + Vault KV v2, pytest suites in `tests/`.

**Spec:** the assessment in this conversation (2026-10-18) and the upstream release notes: https://github.com/kagent-dev/kagent/releases/tag/v1.0.0-alpha12, `…/alpha13`, `…/alpha14`. Breaking PRs: kagent#3223 (kmcp removed), #3160 (two Postgres logins), #3153 (config file replaces env vars), #3207 (`push` moved to top level), #3151 (Harness image catalog), #3067 (worker pool ServiceAccount), #3080 (`spec.harnessRef` required; already satisfied).

## Decisions (made for this plan; confirm at review)

| Decision | Choice | Alternative not taken |
|---|---|---|
| What replaces kmcp | **Plain Deployment + Service + ConfigMap + ServiceAccount per server, same names kmcp used** (`agent-docs-mcp`, `brave-search-mcp`, `implementer-mcp`), running `ghcr.io/agentgateway/agentgateway:0.9.0-musl` exactly as kmcp did. | A separate Argo Application for the standalone `kmcp` 0.4.0 chart + `kmcp-crds` 0.4.0. Upstream calls kmcp "unmaintained KMCP-era cruft" (kagent#3223) and the CRD hand-over between two charts is the riskier operation. |
| How the hand-over avoids an outage | The `kagent-secrets` Application gets `PrunePropagationPolicy=orphan` for one sync: Argo applies the plain manifests onto the kmcp-owned objects (SSA co-management), prunes the `MCPServer`s, and the orphan finalizer strips the ownerReferences instead of garbage-collecting the Deployments. The option is reverted in a follow-up PR. | Foreground prune: GC deletes the four objects, Argo recreates them seconds later. Every agent run starting in that window fails at MCP init. |
| Postgres logins | Keep `kagent_v1_user` (Vault `v1-user`) as the **owner** login; add NOLOGIN role `kagent_readwrite` and login `kagent_v1_readwrite_user` (Vault `v1-readwrite-user` / `v1-readwrite-password`) on the existing `kagent-db` key and Vault role. | Renaming the owner login to upstream's `kagent_owner_user`: more rotation surface for no gain. |
| Database reset | Drop and recreate **both** `kagent_v1` and `substrate`, as the runbook says, even though Substrate's pin does not move (kagent sessions reference Substrate actors; a reset leaves no orphans). | Reset only `kagent_v1`. |
| Runtime telemetry | `config.runtimeDefaults.telemetry` gets the same Coroot OTLP targets as the controller, so agent sandboxes keep exporting traces and logs as on alpha11. | Leave it empty (agents stop exporting). |
| Eval gate after the bump | Expect every agent to be re-scored (the Harness image digest is in each agent's definition hash) and `homelab-knowledge` to be held on the `memory` entry (clean database). Reseed memory and re-score; do not lower the baseline by hand. | Pre-seed is impossible: the PostSync Job runs before anyone can write to the new database. |

## Global Constraints

- Everything through Git and PRs. No `kubectl apply/edit/patch` on Git-managed resources (`AGENTS.md`). The only imperative steps are the runbook's archive/drop/sync of databases and Vault provisioning, which the owner runs.
- Merge only on the owner's explicit "Merge"; rebase merges only, `gh pr merge <n> --rebase --admin` (ruleset). One push per PR (Atlantis plan lock), though none of these PRs touch `terraform/`.
- Never commit secret values. Passwords are 64 hex characters generated by `scripts/provision-kagent-1-0-vault.sh` (URL-safe, no escaping).
- Every image pinned by digest (`disallow-latest-tag` admission policy; Renovate `pinDigests`). Chart images are pinned through `tag: "<version>@sha256:…"` because the chart image helpers take no digest key.
- Digests resolved 2026-10-18 for 1.0.0-alpha14: controller `sha256:7f9958d696623b04332519e2a0a22c756724539c9e269f6ee626e0aeb102cd42`, ui `sha256:3795ceebd70e3e17d2fb6500ffab1eb8d1f366c4c605ba90d90c9f811ef0344d`, golang-adk `sha256:eb1b0c7f635f31d464cff7cf212275f2642057a629ed20b39661e9f644f71f21` (the chart's own release catalog), `kagent-crds` chart `sha256:f51c1732f1a032276246169cb2fb85eb3dc072ee08df58ea8b45d4b35f41d5e9`, agentgateway `0.9.0-musl@sha256:aa375451b6f925f6b260fe33cbe237555efd322f14f3b5e0c717628a069cfb0a`. Re-resolve with `crane digest <image>` before use if a tag was re-pushed.
- Unchanged and must stay so: Substrate `v0.5.0-alpha2` (kagent alpha14's `go/go.mod` pins the same), `kagent-tools` chart 0.3.0, `a2a-go` v2.6.0 (the A2A client `scripts/kagent_a2a.py` needs no change).
- CI runs each pytest suite separately: `python -m pytest tests/<suite>/ -q`. Generated files (`base-apps/index.md`, each `docs/`, `mkdocs.yml`, the eval-gate ConfigMap) are regenerated, never hand-edited.
- PR titles and bodies describe the change accurately (pr-triage input). A PR touching `base-apps/**` may get an `okf-autosync` bot commit: pull before pushing again.

## Review Focus

1. **An agent run that starts while a MCP server Deployment is rolling** must fail with the documented `failed to init MCP session … Service Unavailable` and nothing else. Task 1 keeps the Service and names stable; Task 4 verifies with a live `ask-hk` during the sync.
2. **`init-kagent-v1-db` re-run against the existing database** (before the reset) must add the read/write role and login without touching `kagent_owner`, and must fail loudly if `kagent_readwrite` already exists with other attributes. Task 6's test pins the role list; the acceptance in Task 7 runs it against the live database.
3. **A controller started with the owner Secret missing** fails at startup with a validation error (alpha14 requires `database.owner.urlFile` unless `skipMigrations`). Task 8 renders the chart and asserts both Secret mounts exist.
4. **Idle-TTL units**: alpha11 took `720h`; alpha14 takes seconds. A typo (`720s`) would delete sessions after twelve minutes. Task 8 asserts the rendered `controller.yaml` contains `idleTtl: 2592000s`.
5. **The eval gate after a clean database**: the first alpha14 run can score before the controller is Ready ("every capture failed", re-scored on the next sync) and usually resets every baseline (new hash → new shared sample → `baseline_reset: true`), which releases on anything but a hard failure; `memory-recall-favorite-color` fails and lowers the new baseline. Task 10 step 5 re-syncs, reseeds memory and deletes only the `hashes` entry so the baseline is kept and raised; a hard failure or a hold anywhere stops the acceptance.

```python
"""The three stdio MCP servers are plain Deployments (§T.126): agentgateway wraps the stdio
server and serves it on :3000, under the names kmcp used, so the RemoteMCPServers' URLs and the
container-name-keyed alerts keep working. kagent 1.0.0-alpha14 removed kmcp (kagent#3223)."""
from pathlib import Path
import yaml
import pytest

REPO = Path(__file__).resolve().parents[2]
SERVERS = {
    "agent-docs-mcp": ("agent-docs-mcp-remote.yaml", "agent-docs", "agent-docs-github-mcp-token"),
    "brave-search-mcp": ("brave-search-mcp-remote.yaml", "brave-search", "brave-search-mcp-api-key"),
    "implementer-mcp": ("implementer-mcp-remote.yaml", "implementer", "implementer-github-app"),
}
ADAPTER = "ghcr.io/agentgateway/agentgateway:0.9.0-musl@sha256:"


def docs(name):
    return [d for d in yaml.safe_load_all((REPO / "base-apps/kagent" / f"{name}.yaml").read_text()) if d]


def one(name, kind):
    found = [d for d in docs(name) if d["kind"] == kind]
    assert len(found) == 1, (name, kind)
    return found[0]


@pytest.mark.parametrize("name", sorted(SERVERS))
def test_no_mcpserver_cr_remains(name):
    assert all(d["kind"] != "MCPServer" for d in docs(name))


@pytest.mark.parametrize("name", sorted(SERVERS))
def test_deployment_runs_agentgateway_around_the_stdio_server(name):
    dep = one(name, "Deployment")
    assert dep["metadata"]["name"] == name
    pod = dep["spec"]["template"]["spec"]
    init = pod["initContainers"][0]
    assert init["image"].startswith(ADAPTER) and init["args"] == ["--copy-self", "/adapterbin/agentgateway"]
    main = pod["containers"][0]
    assert main["name"] == "mcp-server"
    assert main["command"] == ["/adapterbin/agentgateway"] and main["args"] == ["-f", "/config/local.yaml"]
    assert main["ports"] == [{"name": "http", "containerPort": 3000}]
    assert "@sha256:" in main["image"]
    assert pod["serviceAccountName"] == name
    assert main["envFrom"] == [{"secretRef": {"name": SERVERS[name][2]}}]


@pytest.mark.parametrize("name", sorted(SERVERS))
def test_config_serves_mcp_on_3000_from_a_stdio_target(name):
    cfg = yaml.safe_load(one(name, "ConfigMap")["data"]["local.yaml"])
    bind = cfg["binds"][0]
    assert bind["port"] == 3000
    route = bind["listeners"][0]["routes"][0]
    assert [m["path"]["pathPrefix"] for m in route["matches"]] == ["/sse", "/mcp"]
    target = route["backends"][0]["mcp"]["targets"][0]
    assert target["name"] == name and "cmd" in target["stdio"]


@pytest.mark.parametrize("name", sorted(SERVERS))
def test_service_keeps_the_url_the_remote_binds(name):
    svc = one(name, "Service")
    assert svc["spec"]["ports"] == [{"name": "http", "port": 3000, "targetPort": 3000,
                                     "protocol": "TCP", "appProtocol": "kgateway.dev/mcp"}]
    remote_file, remote_name, _ = SERVERS[name]
    remote = [d for d in yaml.safe_load_all((REPO / "base-apps/kagent" / remote_file).read_text())
              if d and d["kind"] == "RemoteMCPServer"][0]
    assert remote["metadata"]["name"] == remote_name
    assert remote["spec"]["url"] == f"http://{name}.kagent:3000/mcp"
    assert svc["spec"]["selector"] == one(name, "Deployment")["spec"]["selector"]["matchLabels"]


@pytest.mark.parametrize("name", sorted(SERVERS))
def test_serviceaccount_mounts_no_token(name):
    assert one(name, "ServiceAccount")["automountServiceAccountToken"] is False


@pytest.mark.parametrize("name", sorted(SERVERS))
def test_pod_template_checksum_matches_the_config(name):
    """agentgateway reads local.yaml once at start. kmcp rolled the pod on config changes through
    a template checksum; here the checksum is written by hand and this test keeps it honest, so a
    stdio-args or tool-list edit in git always restarts the server."""
    import hashlib
    text = one(name, "ConfigMap")["data"]["local.yaml"]
    want = hashlib.sha256(text.encode()).hexdigest()
    got = one(name, "Deployment")["spec"]["template"]["metadata"]["annotations"]["checksum/config"]
    assert got == want, f"{name}: set checksum/config to {want}"


@pytest.mark.parametrize("name", sorted(SERVERS))
def test_deployment_selector_is_the_immutable_pair_kmcp_set(name):
    """kmcp's Deployments select on instance+name. A selector is immutable, so the manifest that
    Argo applies onto the live object must carry exactly that pair or the hand-over is rejected."""
    want = {"app.kubernetes.io/instance": name, "app.kubernetes.io/name": name}
    dep = one(name, "Deployment")
    assert dep["spec"]["selector"]["matchLabels"] == want
    labels = dep["spec"]["template"]["metadata"]["labels"]
    assert all(labels.get(k) == v for k, v in want.items())
    assert one(name, "Service")["spec"]["selector"] == want
```

# scope) — see agent-docs-mcp-external-secret.yaml.

# A plain Deployment since §T.126. Until then kmcp's MCPServer CR rendered exactly this shape:
# an init container copies the agentgateway binary into an emptyDir, and the main container
# runs agentgateway, which starts the stdio server as its child and serves it as Streamable
# HTTP on :3000 (/mcp and /sse). kagent 1.0.0-alpha14 removed kmcp (kagent#3223), so the shape

# checksum/config = sha256 of the local.yaml text; CI fails when it is stale
# (tests/agent-identity/test_mcp_server_manifests.py), so every config edit in git rolls the pod.
# Recompute:  yq '.data["local.yaml"]' <file> | sha256sum   (ConfigMap document only)
# The stdio child inherits the container environment, which is how the token (envFrom the
# ExternalSecret's Secret) reaches it without appearing in this file.
apiVersion: v1
kind: ServiceAccount
metadata:
  name: agent-docs-mcp
  namespace: kagent
  labels:
    app.kubernetes.io/part-of: kagent
    app.kubernetes.io/name: agent-docs-mcp
automountServiceAccountToken: false
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: agent-docs-mcp
  namespace: kagent
  labels:
    app.kubernetes.io/part-of: kagent
    app.kubernetes.io/name: agent-docs-mcp
data:
  local.yaml: |
    binds:
      - port: 3000
        listeners:
          - name: default
            protocol: HTTP
            routes:
              - name: mcp
                matches:
                  - path:
                      pathPrefix: /sse
                  - path:
                      pathPrefix: /mcp
                backends:
                  - weight: 100
                    mcp:
                      targets:
                        - name: agent-docs-mcp
                          stdio:
                            cmd: ./github-mcp-server
                            args:
                              - stdio
                              - --read-only
                              - --toolsets
                              - repos
    config: {}
---

kind: Service
metadata:
  name: agent-docs-mcp
  namespace: kagent

    app.kubernetes.io/part-of: kagent

  selector:
    app.kubernetes.io/instance: agent-docs-mcp
    app.kubernetes.io/name: agent-docs-mcp

      port: 3000
      targetPort: 3000

      app.kubernetes.io/instance: agent-docs-mcp
