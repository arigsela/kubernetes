# Homelab Platform — Knowledge Bundle

> **For agents:** Start here. Traverse: this bundle root → a directory `index.md` → an app's `docs.md`/`runbook.md` → the `sources:` files listed in that doc. This root is a **navigation/summary layer**; the `sources:` files are authoritative. If a summary here looks wrong, go read the source.

This repository's **knowledge documents** are [Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md) (OKF v0.2) documents: markdown with YAML frontmatter, living beside the manifests they describe. Every `docs.md`/`runbook.md` is an OKF concept document (`type`, `title`, `description`, OKF's `status` and `sources`, plus this repo's own contract fields). This file and each directory `index.md` play the role of OKF's directory listing.

The repository as a whole is **not** a strictly conformant OKF bundle, and does not try to be: `README.md`, `CLAUDE.md`, and the specs and plans under `docs/` carry no frontmatter, which OKF §11 requires of every non-reserved `.md`, and the in-repo `index.md` files carry frontmatter and tables, which §8 does not allow. For a strictly conformant, portable bundle, run `scripts/gen-okf.py --export <dir>`. It exports navigation and concept documents only, rewrites the index files as §8 listings, and derives OKF's trust and lifecycle fields (`generated`, `verified`, `stale_after`) from git and `last_reviewed`. That is what to hand an agent that should not get the whole infrastructure repo. See `templates/agent-docs/README.md` for the authoring contract.

## 1. System context
- Kubernetes API: `https://10.0.1.50:6443` (k3s: one control-plane node, two workers)
- GitOps: Argo CD watches this repo; the app-of-apps "master-app" (defined in `base-apps/master-app.yaml`, which it manages itself) creates an Application per top-level `.yaml` in `base-apps/`. 15 apps skip that hand-written file entirely: they're generated by the `managed-apps` ApplicationSet (`base-apps/managed-apps.yaml`) from configs in `appsets/managed-apps/` — see `docs/managed-apps-appset.md`.
- Secrets: HashiCorp Vault at `vault.vault.svc.cluster.local:8200` (KV v2, path `k8s-secrets`), surfaced via External Secrets Operator. Human login to Vault is via **Dex OIDC** (`dex.arigsela.com`) fronting GitHub; the UI is at `vault.arigsela.com`.
- S3 buckets: `asela-terraform-states` (Terraform state), `asela-chores-loki-logs-*` (Loki), `asela-agent-audit-record` (the durable agent action record — a write-only IAM user for the exporter and a List/Get-only one for agent-audit-web, provisioned via Crossplane at `base-apps/agent-audit-aws-infrastructure/`). ECR `agent-audit-web` (us-east-2) holds that app's image, pushed by a GitHub-OIDC role in the same directory.

## 2. Platform topology
- **Argo CD** (`base-apps/argo-cd/`) — control plane; master-app pattern.
- **base-apps/** — most apps get one hand-written Application; 14 are instead generated by the `managed-apps` ApplicationSet (see below). Each app directory holds its manifests and (in-scope) its agent-docs contract.
- **appsets/managed-apps/** — config files (one per managed app) driving the `managed-apps` ApplicationSet; see `docs/managed-apps-appset.md`.
- **terraform/** — `roots/asela-cluster` is the active root; reusable `modules/`.
- **ansible/** — host layer: the libvirt hypervisor (`asela-k8s`) and the k3s VMs; baseline, patching, and the control plane's kube-apiserver authn config. See `ansible/README.md`.
- **Crossplane** — declarative cloud resources.

## 3. GitOps data flow
`git commit` → Argo CD detects drift → syncs manifests to the cluster (`prune: true`, `selfHeal: true`). Secrets resolve at runtime: `SecretStore` + `ExternalSecret` → Vault.

## 4. Cross-cutting concerns
- **Secrets:** Vault + External Secrets Operator; per-namespace `SecretStore`. Agent credentials are **path-scoped per consumer** (dedicated ESO ServiceAccount + SecretStore + Vault role + key) — never the broad `vault-backend` store or a shared key. See the agent-identity contract.
- **Human authentication:** Dex OIDC (`base-apps/dex/`, `dex.arigsela.com`) fronting GitHub, used for Vault, Argo CD, kubectl and agent-audit-web login. See `base-apps/dex/docs.md` and `docs/troubleshooting/kubectl-oidc.md`.
- **TLS/certs:** cert-manager (`base-apps/cert-manager/`) issuing from Let's Encrypt through a single `letsencrypt-route53` issuer (Route 53 DNS-01). Each host has an explicit `Certificate` in its app directory, served by the Istio Gateway.
- **Ingress/mesh:** Istio Gateway API (`base-apps/istio-ingress/`): one Gateway, a per-host `HTTPRoute` + `Certificate`, and an IP allow-list `AuthorizationPolicy`; the Coraza WAF runs on the gateway (`base-apps/istio-waf/`). The Istio ambient dataplane is installed, but no namespace is enrolled.
- **Agents:** kagent **1.0** (`base-apps/kagent/`, `api.kagent.dev/v1alpha3`: an `AgentTemplate` for what an agent does, a `Harness` for how it runs, an `Agent` binding the two) on **Agent Substrate** (`base-apps/substrate/`): each conversation is a gVisor actor in a shared worker pod, snapshotted to rustfs when idle. Seven agents on Claude Sonnet 5.5 / Haiku 5.5; state in database `kagent_v1` on the pgvector Postgres. Reach them over A2A at `https://kagent-mcp.arigsela.com/agents/kagent/<agent>` (`scripts/ask-hk` for "ask hk") or the UI at `kagent.arigsela.com`; both hosts are IP allow-listed and A2A is otherwise unauthenticated.
- **Agent guardrails (L03):** kagent agents run under two admission-enforced contracts — **identity** (`agent-identity-*`, scoped credentials, explicit tool lists) and **capability** (`agent-capability*`, per-template `read`/`write`/`admin` classes, a fail-closed tool taxonomy, HITL approval on every binding that holds a mutating tool, no sub-agent escalation, agents only by template + harness reference, and only the `kagent` runtime on pinned images). Both are native ValidatingAdmissionPolicies in the API server (`[Deny]`, failurePolicy `Fail`; `base-apps/admission-policies/`), mirrored by CI validators (`scripts/validate-agent-*.py`). See `docs/adp-engineering-deep-dive.md`; the concept as presented to leadership, with this platform as the anonymized reference, is `docs/presentations/adp-concept-infographics.pdf`.
- **Observability:** Loki (logs, S3-backed) + Grafana + Coroot (eBPF traces/metrics). Plus the **agent action record** — kagent's tool-call history (who called what, with what args, approved or not) surfaced read-only, redacted, exported daily to S3, and checked by a scheduled job (`base-apps/postgresql/agent-audit-cronjob.yaml`, `scripts/agent-audit.py`), and browsable at `agent-audit.arigsela.com` (`base-apps/agent-audit-web/`, app repo `arigsela/agent-audit-web`). **Alerting:** Falco → Loki and Grafana alert rules → an n8n webhook. See `docs/adp-resources-and-observability.md` for where to look.
- **PR review triage:** every PR to `main` gets `review:skip|skim|read` plus one sticky comment from `.github/workflows/pr-triage.yaml`, which runs the `pr-triage` action from `arigsela/claude-agents`. It applies policy rules, then Jev, then Claude Haiku only when Jev is unsure. The policy is `.github/review-policy.yaml`, read at the PR's base commit. Labels only, never blocking. Companion Claude Code skills: `/pr-explainer` and `/review-retro`.
- **Promotion:** `.github/workflows/promote.yaml` + `scripts/promote.py` merge two classes without a human, both needing `review:skip` and every check and status green: Renovate PRs whose diff is docs-only or image-tag bumps (≤2 files, outside a deny list), and the owner's docs-only PRs (`*.md` or `docs/`, ≤10 files, never `.github/`, `.claude/`, `CLAUDE.md`, `AGENTS.md`, `templates/`), under `.github/promotion-policy.yaml` read at `main`. The merge is done by a dedicated GitHub App (`arigsela-promotion`, ruleset bypass in pull-request mode), a different principal from Renovate's. Everything else waits for the owner. See `docs/platform/promotion.md`.
- **Dispatcher:** Grafana alerts also reach `base-apps/dispatcher/` (`scripts/dispatch.py`), which routes each alert title by a declared table to a read-only kagent investigation as the `dispatcher` identity (or to nobody), budgeted per hour and deduplicated per fingerprint; findings go through n8n to Slack with secrets scrubbed, with the session id to continue by hand. The human alert path is unchanged, and the dispatcher never answers an approval.
- **Agent evaluation:** a golden-answer corpus (`tests/eval-corpus/`) + scorer (`scripts/score-eval.py`) grade agent answers, including that they refuse to leak secrets. The judge is a Jev-then-Sonnet cascade (`--judge`), calibrated in `tests/eval-corpus/calibration/`.

## 5. Known gaps
| Gap | Recommendation | Source |
|---|---|---|
| Not every app carries the full agent-docs contract | Backfill stubs in `base-apps/index.md` under CI gating | `base-apps/index.md`, `scripts/agent-docs-scope.txt` |
| L02 golden paths are fragmented, not registered | A declarative path registry humans + agents can invoke; today there is the Backstage New App template (`templates/new-app/`) and the dormant Crossplane XApplication, and both still emit an nginx Ingress (SPEC T76) | `docs/superpowers/specs/2026-07-14-adp-remaining-pillars-roadmap.md` (P2–P4) |
| Evaluation covers what an agent SAYS; what it DOES under pressure is thinly tested | Since 2026-10-17 the PostSync Job `eval-gate` scores EVERY agent whose definition changed (V93, V99): its own corpus plus a shared adversarial corpus (35 red-team prompts, sampled) and credential canaries planted in `eval-canary`, with tool calls scored (`expect_tools`/`forbid_tools`; approval pauses rejected) and a release gate that keeps a regressed agent away from the dispatcher and the Slack bridge. Still open: the judge keys (`scripts/provision-eval-gate-vault.sh`) and tool-aware attacks beyond the canaries | `base-apps/kagent/docs.md`, `tests/eval-corpus/` |
| kagent `Execution` pillar partly addressed | Since 2026-10-11 every session runs in a gVisor sandbox on Agent Substrate, and model keys are injected at egress instead of handed to the agent. Still open: sandbox egress has no destination allow-list and Substrate is an alpha with single-replica components. A2A callers are verified principals since 2026-10-13 (V91, V92; `base-apps/kagent/docs.md`); still open there: per-person UI login, and the runtime's own calls reach the controller in plaintext from `ate-system` | `base-apps/substrate/docs.md`, `base-apps/kagent/docs.md`, same roadmap |
